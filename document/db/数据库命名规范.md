# SPECTRA 数据库命名规范

> 适用范围：SPECTRA 平台所有数据库对象（表、字段、索引、约束）
>
> 目标：**边界清晰、可扩展、可拆分、可维护**

---

## 一、总体设计原则

### 1. 分层清晰（最重要）

数据库对象必须体现 **系统层级与业务边界**：

* **平台 / 核心能力层（Core）**：`SYS_`
* **基础资源域（如组织）**：按资源域前缀
* **业务域（Business Domain）**：按业务域前缀

> ❌ 禁止所有业务表统一使用 `BIZ_`

---

### 2. 前缀即边界

> 一个前缀 = 一个逻辑域 / 子系统

* 用于权限、拆库、服务治理
* 禁止不同业务共用一个前缀

---

### 3. 命名稳定性优先

* 表名、字段名一旦上线，**原则上不修改**
* 宁可冗长，也不要语义模糊

---

## 二、表命名规范

### 1️⃣ 核心平台表（SYS_）

**用途**：

* 身份、权限、组织、配置、审计
* 不承载任何具体业务数据

**前缀**：

```
SYS_
```

**示例**：

```
SYS_USER
SYS_ROLE
SYS_REL_USER_ROLE
SYS_ROLE_DATA_SCOPE
SYS_ROLE_DATA_SCOPE_TARGET
SYS_DICT
SYS_CONFIG
SYS_AUDIT_LOG
```

**强制规则**：

* SYS 表 **不得外键依赖任何业务表**
* 业务表可以引用 SYS 表

---

### 2️⃣ 基础资源域表（推荐）

用于跨业务复用的“基础资源”。

#### 示例：组织域（ORG_）

```
ORG_ORGANIZATION
ORG_ORG_RELATION
ORG_ORG_MEMBER
```

#### 示例：文件域（FILE_）

```
FILE_OBJECT
FILE_BUCKET
```

---

### 3️⃣ 业务域表（强烈推荐）

> 业务表 **必须** 使用业务域前缀

**命名规则**：

```
{DOMAIN}_ + 表名
```

#### 示例：项目域（PRJ_）

```
PRJ_PROJECT
PRJ_PROJECT_MEMBER
PRJ_PROJECT_ROLE
```

#### 示例：订单域（ORD_）

```
ORD_ORDER
ORD_ORDER_ITEM
ORD_REFUND
```

---

### 4️⃣ 关联 / 中间表命名

**规则**：

```
{域前缀}_REL_{主体1}_{主体2}
```

**示例**：

```
SYS_REL_USER_ROLE
PRJ_REL_PROJECT_USER
```

---

## 三、字段命名规范

### 1️⃣ 通用字段（所有表推荐）

```sql
ID           BIGINT                              -- 主键
CREATED_BY   NUMBER(19, 0),                      -- 创建人
CREATED_AT   TIMESTAMP WITH TIME ZONE NOT NULL,  -- 创建时间
UPDATED_BY   NUMBER(19, 0),                      -- 最后更新人
UPDATED_AT   TIMESTAMP WITH TIME ZONE NOT NULL,  -- 最后更新时间
DELETED      TIMESTAMP WITH TIME ZONE,           -- 是否删除
VERSION      NUMBER(19, 0) DEFAULT 0             -- 乐观锁
```

---

### 2️⃣ 外键字段命名

```text
{引用表名}_ID
```

**示例**：

```
USER_ID
ROLE_ID
ORG_ID
PROJECT_ID
```

---

### 3️⃣ 枚举 / 类型字段

```text
*_TYPE
*_STATUS
```

**示例**：

```
SCOPE_TYPE
TARGET_TYPE
USER_STATUS
ORDER_STATUS
```

---

## 四、索引命名规范

### 1️⃣ 主键索引

```text
PK_{TABLE_NAME}
```

### 2️⃣ 唯一索引

```text
UK_{TABLE_NAME}_{COLUMN}
```

### 3️⃣ 普通索引

```text
IDX_{TABLE_NAME}_{COLUMN}
```

---

## 五、约束与设计禁令

### ❌ 禁止事项

* SYS 表引用业务表
* 不带前缀的业务表
* 表名使用动词
* 字段名使用拼音
* 不同语义字段复用同一名称

---

## 六、数据权限设计特别约定（SPECTRA 特性）

### 1️⃣ 数据范围表统一归属 SYS

```
SYS_ROLE_DATA_SCOPE
SYS_ROLE_DATA_SCOPE_TARGET
SYS_USER_DATA_SCOPE
SYS_USER_DATA_SCOPE_TARGET
```

### 2️⃣ 业务表需具备权限锚点字段

```text
ORG_ID   （当前阶段强制）
```

未来可扩展：

```text
DEPT_ID
PROJECT_ID
```

---

## 七、推荐的整体前缀规划示例

```
SYS_  平台核心
ORG_  组织/租户
PRJ_  项目
WF_   工作流
ORD_  订单
FIN_  财务
FILE_ 文件
```

---

## 八、规范落地建议

1. 新表必须先确定 **域前缀**
2. 表结构评审时强制检查命名
3. 规范作为 Code Review Checklist
4. 不允许“临时命名，后期再改”

---

> 本规范为 SPECTRA 平台长期演进的基础约定
>
> **命名不是形式，而是架构的一部分**
